# The Fort: iOS app (Capacitor 8)

The iOS app wraps the one-file game (`../index.html`, the same file GitHub Pages serves) in a
Capacitor shell. The setup mirrors Euchre Unleashed's: Capacitor 8 with Swift Package Manager
plugins, manual signing with the team's one distribution certificate, fastlane, TestFlight builds
from GitHub Actions (`../CI_SETUP.md`).

- **Bundle id:** `com.thefort.game` (it can't change once the app is published). **App Store name:**
  The Fort: Last Stand ("The Fort" was taken); the home-screen name is The Fort. App Store Connect
  Apple ID 6816787587, SKU `thefort001`.
- **Devices:** iPhone, portrait and landscape (the game lays itself out for both). iPads run the
  iPhone build.
- **Plugins** (versions pinned to the set Euchre ships): `@capacitor-community/admob` 8.0.0
  (rewarded and interstitial ads, ATT, UMP consent), `@revenuecat/purchases-capacitor` 13.2.1 (gem
  shop), `@capacitor/local-notifications`, `@capacitor/haptics`, `@capacitor/preferences` (native
  copy of the save), `@capacitor/app` (background and foreground), `@capacitor/splash-screen`, and
  the local `plugins/capacitor-gamekit` (Game Center, copied from Euchre).

## How the game talks to the device

```
index.html  Plat (the "PLATFORM (Plat)" section) ──> window.Shell (shell.js) ──> Capacitor plugins
```

`build_www.py` injects `capacitor.js` and `shell.js` into `<head>`, so `window.Shell` exists
before the game's script defines `Plat`. The web build never loads them. There, `Plat` hides ads
and purchases, and the save lives in localStorage only. `Plat` never calls a plugin directly;
`shell.js` does, and every call degrades instead of throwing: no ad means `false`, a failed
purchase grants nothing.

| Game side (`Plat`) | Shell | Plugin calls |
|---|---|---|
| `Plat.boot()` at startup | `store.hydrate`, `configure`, `iap.owned`, `app.onState`, `ready` | Preferences, ATT, UMP, preloads, RevenueCat, SplashScreen.hide |
| `Plat.ad(kind)` | `ads.showRewarded()` → `{ rewarded, reason? }` | `prepareRewardVideoAd` / `showRewardVideoAd`; settles on `onRewardedVideoAdDismissed` |
| `Plat.interstitial()` | `ads.showInterstitial()` → `{ shown }` | `prepareInterstitial` / `showInterstitial` |
| `Plat.buy(sku)` | `iap.purchase(id)` → `{ ok, cancelled?, error? }` | `getProducts` + `purchaseStoreProduct` |
| `Plat.restore()` | `iap.restore()` → owned ids, or rejects with a message | `restorePurchases`, `syncPurchases` as a fallback |
| `Plat.notify` / `Plat.cancel` | `notify.schedule({id, at, title, body})` / `notify.cancel(id)` | LocalNotifications; the string id is hashed to an int |
| `Plat.haptic(kind)` | `haptic(kind)` | `Haptics.impact` / `Haptics.notification` |
| `Plat.price(sku, usd)` | `iap.price(id)` | the localized `priceString` |
| `Plat.score('daily', wave)` | `gc.submitScore(board, n)` | GameKit (only once `PLAT_IDS.lbDaily` is set) |
| `saveWrite(json)` on every `save()` | `store.put(key, json)` | `Preferences.set` (debounced; flushed when the app goes to the background) |

What the shell handles for the game:

- **ATT at launch**, before any ad loads. App Review looks for the prompt there. The notification
  permission sheet waits until ATT has settled. Ads are non-personalized (`npa`) unless ATT is
  authorized and UMP consent is obtained or not required.
- **Ad loading.** A rewarded ad is preloaded at launch and after every show. A tap while one is
  still loading waits up to 6 s; after that the game shows "No ad available right now". An
  interstitial is preloaded once the player is past the interstitial roll-out; a slow one is
  skipped. A show that never reaches the screen is settled by an 8 s watchdog. Game audio is
  suspended while an ad is up.
- **Save durability.** iOS can purge a WKWebView's localStorage. Every save is mirrored to
  Preferences (UserDefaults) with a sequence number. At launch, `Shell.store.hydrate()` puts the
  native copy back when localStorage had no save or holds an older one. The splash screen stays up
  until then, so the player never sees a fresh save flash by. Euchre has no iCloud sync, so The Fort
  doesn't either; the Settings "Back up progress" code is the cross-device path.
- **Backgrounding.** `appStateChange` saves and pauses a running battle, the same as the web's
  `visibilitychange`, and flushes the native save copy at once.

## Layout

```
shell.js            window.Shell over the plugins; plain ES5, no bundler
build_www.py        ../index.html + capacitor.js + shell.js + fonts/ -> www/ (build stamp, id checks)
www/                generated by build_www.py (gitignored; never edit)
fonts/              Inter + Oxanium woff2 (OFL), so the app renders offline; replaces the Google Fonts link
ios/                the Xcode project (committed); fastlane/ holds the CI lanes
  App/App/FortViewController.swift   home indicator auto-hide, edge swipes deferred
  App/App/Info.plist                 AdMob app id, ATT text, SKAdNetwork ids, orientations
  App/App/PrivacyInfo.xcprivacy      UserDefaults (CA92.1) for the save mirror
plugins/            capacitor-gamekit, installed as a file: dependency
assets/             art.html + render_art.py draw icon-only.png and splash*.png (@capacitor/assets sources)
fix_spm_paths.cjs   capacitor:sync:after hook: a sync on Windows writes backslash SPM paths; this fixes them
test_shell.cjs      shell.js against mocked plugins in plain Node (94 checks)
check_game.cjs      ../index.html: scripts compile, PLAT_IDS keys, fort_ product ids, Shell contract
check_www.cjs       the built www/: injection order, offline, every referenced file present
test_plat.py/.js    the game's Plat against a scripted Shell, in headless Edge (local only)
```

## Build and test (Windows is fine; compiling iOS needs the CI runner)

Run `npm ci` in `native/` once. After any change to `index.html` or `shell.js`:

```
python native/build_www.py
node native/test_shell.cjs
node native/check_game.cjs
node native/check_www.cjs
python native/test_plat.py
cd native && npx cap sync ios
```

`python native/build_www.py --release` builds with the live AdMob units instead of Google's test
units. `npx cap sync ios` works on Windows. Builds reach TestFlight only through
`.github/workflows/ios.yml`; see `../CI_SETUP.md`.

Icon and splash: edit `assets/art.html` (`?show=1` previews it in a browser), then run
`python native/assets/render_art.py` and `npx capacitor-assets generate --ios` in `native/`.

## Ids and where they live

All of them are public by design (they ship inside every build), so they sit in the repository.

| What | Where | Value |
|---|---|---|
| AdMob app id | `index.html` `PLAT_IDS.admobApp` **and** `ios/App/App/Info.plist` `GADApplicationIdentifier` (build_www.py refuses a mismatch) | `ca-app-pub-8913077727879528~2474795069` |
| Rewarded unit, live | `PLAT_IDS.rewarded` | `ca-app-pub-8913077727879528/5913234786` |
| Interstitial unit, live | `PLAT_IDS.interstitial` | `ca-app-pub-8913077727879528/3784007309` |
| Rewarded / interstitial, test | `PLAT_IDS.testRewarded` / `testInterstitial` | Google's public iOS test units |
| RevenueCat public App Store key | `PLAT_IDS.rcKey` | `appl_CoLlGppaiooTIcoxtSShLvmUqxA` (project "The Fort") |
| Game Center leaderboard (recurring daily, best wave) | `PLAT_IDS.lbDaily` | **PLACEHOLDER**: empty, Game Center off |
| ATT prompt text | `Info.plist` `NSUserTrackingUsageDescription` | written; review it |
| SKAdNetwork ids | `Info.plist` `SKAdNetworkItems` | Google's list, fetched 2026-09-27 |
| Marketing version | Xcode project `MARKETING_VERSION` (both configurations) | `1.0.0` |

**Test ads unless release.** `build_www.py` stamps the ad mode into the page. Without `--release`
(Xcode debug builds, ordinary TestFlight runs) the game uses Google's test units, so nobody taps a
live ad by accident. With `--release` (the workflow's `release` input: the build you submit to App
Review) it uses the live units. The Settings build line reads "... · test ads" on a test build.

The UMP consent form shows only if a GDPR message is published in AdMob > Privacy & messaging.
Without one, EEA users get non-personalized ads and no form.

## In-app products

**Not created yet.** Create each one in App Store Connect and in RevenueCat under the same id. Until
they exist the shop still shows (RevenueCat is configured), prices fall back to the USD labels, and
a purchase ends in "Purchase failed · not in the App Store yet". App Store product ids
are unique across a developer account, and Euchre already sells `remove_ads` and `coins_*`, so
every Fort id is `fort_`-prefixed. Prices are set in App Store Connect; the USD values in
`index.html` are only the fallback label before the store answers.

| Product id | Type | Grants | Price tier |
|---|---|---|---|
| `fort_gems_80` | consumable | 80 gems | $0.99 |
| `fort_gems_500` | consumable | 500 gems | $4.99 |
| `fort_gems_1200` | consumable | 1,200 gems | $9.99 |
| `fort_gems_2600` | consumable | 2,600 gems | $19.99 |
| `fort_gems_7000` | consumable | 7,000 gems | $49.99 |
| `fort_starter` | non-consumable | 400 gems + half-price second lab slot, once | $2.99 |
| `fort_noads` | non-consumable | no interstitials (rewarded ads stay optional) | $3.99 |

A RevenueCat entitlement (e.g. `no_ads` on `fort_noads`) is optional: the shell reads owned
products from `allPurchasedProductIdentifiers`, the transactions and the entitlements alike.

The game grants on `{ ok:true }` from `Shell.iap.purchase()` (`shopGrant`). Non-consumables come
back quietly at launch from RevenueCat's cached CustomerInfo, and from "Restore purchases" in the
shop footer. A restore sets the flags (Remove Ads; the Starter Pack's lab voucher); it never pays
the Starter Pack's gems again.
